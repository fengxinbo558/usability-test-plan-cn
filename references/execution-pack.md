# 可用性测试执行包

按当前工作模式选用模板。快速首轮通常合并为一个文档；完整计划可按协作需要拆分文件；受限模式只保留事实、假设、阻塞项和最小补证。高风险控制叠加在所选模式上，不自动改变成品长度。空字段如果与决策无关就删除，不为填表收集额外个人信息。

## 一页研究简报

```markdown
# <研究名称>
- 模式：快速 / 完整 / 受限；高风险控制：适用 / 不适用
- 决策与截止时间：
- 产品、版本与环境：
- 研究问题：
- 不回答的问题：
- 已知事实：
- 工作假设与可能反证：
- 关键用户与必须覆盖单元：
- 关键任务与失败后果：
- 首批参与者组合及覆盖理由：
- 追加招募触发条件：
- 停止条件：
- 执行前置项、限制与未知：
```

## 招募筛选表

只询问能决定纳入、排除或分层的内容。不要以年龄、职位等弱代理变量替代真实行为。

```markdown
| 筛选问题 | 纳入/排除/分层规则 | 与研究问题的关系 | 是否敏感及处理方式 |
|---|---|---|---|
| 最近一次完成相关任务是什么时候？ |  | 验证实际经验 | 否 |
| 在该流程中承担什么角色或权限？ |  | 覆盖关键角色 | 视场景而定 |
| 常用设备、入口或辅助技术是什么？ |  | 覆盖环境差异 | 最小化记录 |
```

不要收集身份证号、银行卡号、账户余额、精确住址或与筛选无关的联系方式。招募与联系若由外部渠道执行，先确认渠道、接收方和字段范围。

## 参与说明与主持开场

```markdown
今天测试的是产品，不是测试你。过程中可以随时暂停或退出，不影响你获得已约定的权益。

- 研究目的：<简短说明>
- 预计时长：
- 将记录什么：屏幕 / 声音 / 笔记 / 不录制
- 数据用途、可见范围和留存期限：
- 不应展示或输入的真实信息：
- 可随时跳过的问题或任务：
- 联系与删除请求方式：

开始前确认：参与者理解以上内容，并同意当前记录方式。
```

这只是研究执行模板，不替代组织适用的正式同意文本、法务或伦理审查。

## 场次前检查

```markdown
- [ ] 产品、原型和任务版本已记录
- [ ] 测试账户、合成身份、测试卡和测试订单可用
- [ ] 不会触发真实支付、通知、删除、发布或清算
- [ ] 录制范围、保存位置和留存期限已确认
- [ ] 屏幕中没有真实身份、客户名单或无关第三方信息
- [ ] 任务起点和成功状态可判定
- [ ] 断线、原型失效、敏感信息暴露和退出预案可用
- [ ] 主持人和观察者知道何时可以提示、何时必须暂停
```

## 场次观察表

一行记录一个可定位事件，不把分析结论写进“原始观察”。

```markdown
| 时间/步骤 | 参与者行为或逐字表达 | 主持提示 | 产品/环境反应 | 暂定问题 | 待核对 |
|---|---|---|---|---|---|
|  |  | 无 / 提示内容 |  |  |  |
```

场次结尾单列：任务结果、参与者信心、最困难步骤、顺利步骤、环境异常和可能反证。

## 问题台账

```markdown
| issue_id | 版本与任务 | 原始证据位置 | 受影响条件 | 后果 | 恢复路径 | 严重度及理由 | 反证 | 建议与待验证项 |
|---|---|---|---|---|---|---|---|---|
```

问题严重度不是观察次数的别名。涉及安全、资金、隐私、合规、数据损失或脆弱人群时，即使只出现一次也要单独升级审查。

## 每批复盘与停止决定

```markdown
- 本批覆盖了哪些用户、任务和环境单元：
- 新增高严重度 / 其他问题：
- 已知问题获得了哪些重复证据或反证：
- 哪些问题的触发条件仍不稳定：
- 尚未覆盖的高风险单元：
- 下一批只需要回答什么：
- 决定：继续定向招募 / 修改后复测 / 在限定范围内停止 / 因资源提前停止
- 决定依据与不能声称的结论：
```

## 报告骨架

```markdown
# 可用性测试结果
## 决策、范围与方法
## 覆盖情况和限制

## 分析推断、反证与替代解释

## 行动建议及验证方式
## 未知信息与下一轮计划
```

报告中的样本内计数写明分子、分母和缺失；除非另有抽样设计，不外推总体比例或显著差异。
